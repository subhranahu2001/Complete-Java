00Lambdas & functional interfaces Java 8

Java 8 (2014) is the most important release in Java's history. Before it, passing behaviour into a method meant a full anonymous inner class. A lambda is a short, anonymous block of code you can pass around like a value — and Streams, Optional and most of modern Java are built on top of it.

Syntax

(a, b) -> a + b                                   // expression body
(String s) -> { System.out.println(s); return s.length(); }   // block body, explicit type
() -> System.out.println("Hello")                 // no parameters
x -> x * x                                        // single parameter: parentheses optional

// Before Java 8
Runnable r = new Runnable() {
    public void run() { System.out.println("Hello"); }
};
// Java 8
Runnable r = () -> System.out.println("Hello");

// the same sort, three ways
names.sort(new Comparator<String>() {
    public int compare(String a, String b) { return Integer.compare(a.length(), b.length()); }
});
names.sort((a, b) -> Integer.compare(a.length(), b.length()));
names.sort(Comparator.comparingInt(String::length));
Definition — functional interface (SAM)

A lambda is an instance of a functional interface: any interface with exactly one abstract method. The lambda supplies that method's body; the compiler picks the interface from the target type of the context. A lambda has no type of its own — Runnable r = () -> {}; makes it a Runnable. Default and static methods do not count. @FunctionalInterface is optional but makes the compiler fail if a second abstract method is ever added.

@FunctionalInterface
interface Calculator { int operate(int a, int b); }

Calculator add = (a, b) -> a + b;
Calculator mul = (a, b) -> a * b;
add.operate(2, 3);   // 5

Trap — effectively final

A lambda can capture a local variable only if it is final or effectively final (never reassigned). The lambda may outlive the stack frame, so the value is captured by copy. This is why int sum = 0; list.forEach(x -> sum += x); does not compile. You can mutate fields of a captured object or the contents of an array — but that is a smell; use reduce or a collector.

Trap — checked exceptions in lambdas

Function, Predicate etc. declare no checked exceptions, so map(path -> Files.readString(path)) does not compile. Catch inside the lambda and wrap in an unchecked exception, or write your own throwing functional interface plus a helper that unwraps it. Only Callable declares throws Exception.

Under the hood — lambda vs anonymous class
  • this inside a lambda is the enclosing instance; inside an anonymous class it is the anonymous object itself.
  • A lambda compiles to invokedynamic + a private synthetic method — no extra .class file, no allocation for non-capturing lambdas (the same instance is reused).
  • Lambdas do not introduce a new scope: a parameter named like a local variable is a compile error. Anonymous classes shadow.
  • Anonymous classes can have state, several methods and extend a class; a lambda implements exactly one method.
Asked — "Can a functional interface have more than one method?"

Yes — any number of default and static methods, and abstract methods that override Object methods (equals) do not count. Comparator has one abstract method plus dozens of defaults. Only one abstract method is allowed.

01Default methods, Optional, java.time Java 8

Default & static methods in interfaces

Why they exist

Before Java 8, adding a method to an interface broke every implementation. Interfaces could never evolve. A default method has a body, so stream() and forEach() could be added to Collection without breaking millions of classes. Static interface methods hold factories (Comparator.comparing). Java 9 added private interface methods so defaults can share helper code without exposing it.

interface Vehicle {
    void start();
    default void honk() { System.out.println("Beep!"); }
    static Vehicle of(String kind) { /* factory */ return null; }
}

// diamond problem: two interfaces with the same default -> you MUST override
class Car implements A, B {
    public void hello() { A.super.hello(); }   // pick one explicitly
}
Asked — "Interface with default methods vs abstract class?"

An abstract class can hold state (fields), constructors and non-public members; a class can extend only one. An interface has no instance state, but a class can implement many. Rule: default methods are for evolving an API and small behaviour; shared state belongs in an abstract class. Resolution order: class methods beat interface defaults; a more specific interface beats a less specific one; otherwise you must override.

Optional — a box holding one value or nothing

Returned by findFirst, min, max, reduce to force the empty case into the type instead of a NullPointerException — the "billion dollar mistake".

Optional<String> a = Optional.of("hi");            // throws NPE if the argument is null
Optional<String> b = Optional.ofNullable(maybeNull);
Optional<String> c = Optional.empty();

a.orElse("default");                // eager: the default is ALWAYS evaluated
a.orElseGet(() -> compute());        // lazy: only when empty
a.orElseThrow();                     // NoSuchElementException (Java 10)
a.orElseThrow(() -> new NotFoundException(id));

int len = a.map(String::trim).map(String::length).orElse(0);
Optional<String> city = findUser(id).flatMap(User::address).map(Address::city);   // flatMap when the mapper returns Optional
Optional.of(42).filter(n -> n > 10);

a.ifPresent(System.out::println);
a.ifPresentOrElse(v -> use(v), () -> log("empty"));        // Java 9
a.or(() -> Optional.of("fallback"));                        // Java 9
users.stream().map(User::cityOpt).flatMap(Optional::stream).toList();   // Java 9: empties vanish
Do this
  • Use Optional as a return type to say "may be absent". Chain with map / flatMap / filter; unwrap with orElse*.
  • Repository: Optional<User> findByEmail(String); service: .orElseThrow(() -> new UserNotFound(email)).
Trap — Optional anti-patterns
  • Fields, method parameters, collection elements — never. Return an empty collection instead of Optional<List>. Optional is not Serializable.
  • if (o.isPresent()) o.get() — a null check with extra steps. Use map / ifPresent.
  • orElse(expensiveCall()) runs the call even when the value is present. Use orElseGet.
  • Optional.of(null) throws; use ofNullable.

02Stream foundations Java 8

A Stream is a sequence of elements supporting sequential and parallel aggregate operations. It is not a data structure: it stores nothing and carries elements from a source through a pipeline of operations. You say what, not how.

The five defining characteristics
  • No storage — pulls from the source on demand.
  • Functional — never modifies the source; filter returns a new stream, the list is untouched.
  • Lazy — intermediate operations do nothing until a terminal operation runs.
  • Possibly unbounded — Stream.iterate is infinite; limit makes it usable.
  • Consumable once — after a terminal operation the stream is closed; reuse throws IllegalStateException.

Anatomy of a pipeline

long count = names.stream()              // SOURCE
    .filter(s -> s.length() == 3)        // intermediate (lazy, returns a Stream)
    .map(String::toUpperCase)            // intermediate (lazy)
    .peek(System.out::println)           // intermediate (lazy)
    .count();                            // TERMINAL - triggers everything, closes the stream

// Imperative vs declarative - same result
int total = 0;
for (String s : names) if (s.length() == 3) total += s.length();

int total = names.stream().filter(s -> s.length() == 3).mapToInt(String::length).sum();

Streams vs loops

Do this — the sentence test

Narrate the pipeline: "From the orders, keep the paid ones, map each to its amount, sum." If the sentence is clean, a stream is right. If you need an index, a break, or you mutate three things per iteration, write a loop. Streams are not faster than loops for simple iteration — they win on readability and on parallel CPU-bound work.

Asked — "Intermediate vs terminal operations?"

Intermediate (filter, map, sorted…) return a new stream and are lazy. Terminal (collect, forEach, reduce, count…) produce a result or side effect and trigger execution. A stream has at most one terminal operation. Follow-up "why lazy?": operation fusion (one pass, not one per stage) and short-circuiting.

04Intermediate operations

Lazy transformations that return a new stream. Stateless ones (filter, map) handle each element independently; stateful ones (sorted, distinct) must see other elements and may buffer everything.

Stream.of("a","bb","ccc").map(String::length)             // 1 2 3       1:1 transform

// flatMap: 1:many, then flatten. map would give Stream<Stream<Integer>>
List<List<Integer>> nested = List.of(List.of(1,2), List.of(3,4), List.of(5));
nested.stream().flatMap(List::stream).toList();               // [1, 2, 3, 4, 5]
Stream.of("hello world", "foo bar").flatMap(l -> Arrays.stream(l.split(" ")));   // 4 words

Stream.of(3,1,2).sorted()                                       // 1 2 3      natural order

Stream.of("a","b").peek(x -> log(x))                            // look, don't touch (debugging only)

Pattern cue — map vs flatMap

Each element becomes exactly one thing → map. Each element becomes a collection / stream / Optional you want merged into one flat stream → flatMap. Lists of lists, words in lines, tags on posts, Optional::stream. Hot path with tiny expansions → mapMulti.

Trap — peek is not for business logic

The JVM may skip peek entirely when the terminal operation does not need the elements (Java 9+ count() on a sized source). Use it for temporary logging only, and remove it after.

Trap — sorted() does not short-circuit

sorted().limit(3) still sorts everything first (O(n log n), O(n) memory); on an infinite stream it never returns. For top-N of a huge stream keep a bounded heap, or put limit before sorted when the order allows.

Definition — the identity in reduce

The identity is the seed and the result for an empty stream. It must satisfy acc(identity, x) == x for every x: 0 for sum, 1 for product, "" for concat. A wrong identity (1 for sum) corrupts results, and in parallel it is applied once per chunk, amplifying the error.

Pattern cue — reduce vs collect

reduce for an immutable single value with an associative operation (sum, max, product). collect for a mutable container (List, Map, StringBuilder) or grouping / partitioning / statistics. Concatenating strings with reduce is O(n²); collect(joining()) is O(n).

Trap — empty streams
  • allMatch and noneMatch on an empty stream return true (vacuous truth); anyMatch returns false.
  • max(), findFirst(), 1-arg reduce return an empty Optional — never call get() blindly.
  • average() on an empty IntStream is an empty OptionalDouble; sum() is 0.
Asked — "findFirst vs findAny?"

findFirst respects encounter order; findAny may return any element and is cheaper in parallel because threads need not coordinate on who was first. Both return Optional and short-circuit. Sequentially they behave the same.

06Comparator deep dive

Streams lean on Comparator everywhere: sorted, min, max, maxBy / minBy, TreeMap. The factory and default methods let you build multi-key orderings declaratively — no hand-written compare.

record Person(String name, int age, double height) {}

Comparator<Person> byAge        = Comparator.comparingInt(Person::age);
Comparator<Person> byAgeDesc    = Comparator.comparingInt(Person::age).reversed();
Comparator<Person> byAgeThenName = Comparator.comparingInt(Person::age).thenComparing(Person::name);
Comparator<String> nat = Comparator.naturalOrder(), rev = Comparator.reverseOrder();

// null-safe
Comparator.nullsFirst(Comparator.naturalOrder());
Comparator.comparing(Person::name, Comparator.nullsLast(Comparator.naturalOrder()));

// in a pipeline: oldest first, ties by name
people.stream().sorted(Comparator.comparingInt(Person::age).reversed().thenComparing(Person::name));
Optional<Person> tallest = people.stream().max(Comparator.comparingDouble(Person::height));

// sort a Map by value, descending
map.entrySet().stream().sorted(Map.Entry.<String,Long>comparingByValue().reversed());

// descending on one key, ascending on the next - reverse ONLY that key
Comparator.comparing(Person::age, Comparator.reverseOrder()).thenComparing(Person::name);

Trap — reversed() reverses everything before it

comparing(age).reversed().thenComparing(name) gives age descending and name ascending — correct if that is what you want. But comparing(age).thenComparing(name).reversed() flips both. Also: Comparator.comparing(p -> p.name()).reversed() often fails to infer the type — use a method reference or Comparator.<Person,String>comparing(...).

Trap — (a, b) -> a - b

Overflows for large values. Use Integer.compare / comparingInt. A comparator must be consistent (transitive, antisymmetric) or sort throws "Comparison method violates its general contract".

Asked — "Comparable vs Comparator?"

Comparable: inside the class, one natural order, compareTo, java.lang. Comparator: outside, many orders, compare(a, b), java.util, works on classes you cannot edit. sorted() with no argument needs Comparable elements and throws ClassCastException otherwise.

07Primitive streams

Stream<Integer> boxes every element into a heap object. IntStream, LongStream, DoubleStream hold raw values and add the numeric aggregates object streams lack.

// object -> primitive
int total = List.of(1,2,3,4).stream().mapToInt(Integer::intValue).sum();     // 10
double avgSalary = staff.stream().mapToDouble(Emp::salary).average().orElse(0);

// primitive -> object
List<Integer> boxed = IntStream.rangeClosed(1,5).boxed().toList();
IntStream.rangeClosed(1,3).mapToObj(i -> "item" + i);

// aggregates only primitive streams have
IntStream.of(2,4,6,8).sum();                        // 20
IntStream.of(2,4,6,8).average().getAsDouble();     // 5.0   (OptionalDouble)
IntStream.of(2,4,6,8).max().getAsInt();            // 8     (OptionalInt)

IntSummaryStatistics st = IntStream.of(2,4,6,8).summaryStatistics();   // count, sum, min, max, average in ONE pass
st.getCount(); st.getSum(); st.getMin(); st.getMax(); st.getAverage();

// int -> long BEFORE it overflows
long big = IntStream.rangeClosed(1, 100_000).asLongStream().map(i -> i * i).sum();
Under the hood — why it matters

Boxing a million ints means a million Integer objects (16 bytes each), cache misses and GC pressure. For sums, averages, ranges and counters, mapToInt before aggregating can be several times faster. Stream<Integer>.reduce(0, Integer::sum) unboxes and re-boxes at every step.

Trap
  • IntStream.average() returns OptionalDouble — getAsDouble(), not get().
  • IntStream.sum() overflows silently at 231; use asLongStream() or mapToLong.

Parallel helps only when ALL of these hold
  1. The dataset is large (10k+ elements) and the per-element work is CPU-bound and non-trivial.
  2. The source splits cheaply: arrays, ArrayList, IntStream.range — not LinkedList, Files.lines, iterate.
  3. Operations are stateless and side-effect free; the combine step is cheap.
  4. You measured. N × Q (elements × cost per element) should be in the hundreds of thousands at least.
Trap — parallel streams hurt when
  • Work is I/O-bound: threads just block, and they block the shared common pool, starving every other parallel stream and CompletableFuture in the JVM. Use a dedicated executor for I/O.
  • You rely on encounter order: forEach order is lost (use forEachOrdered); findAny is non-deterministic.
  • Lambdas touch shared mutable state: forEach(list::add) on an ArrayList is a data race. Collect instead.
  • The reduce identity is not a true identity, or the accumulator is not associative — results silently differ per run.
  • Inside a servlet / @Transactional method: the worker threads do not carry the caller's ThreadLocals (security context, transaction, MDC).
Asked — "How does parallelStream work internally?"

The Spliterator of the source calls trySplit() recursively to halve the data; each chunk runs the pipeline as a ForkJoin task on the common pool; results are merged with the collector's combiner (or the reduce combiner). Order-sensitive ops (sorted, limit, forEachOrdered) impose extra coordination cost.

11CompletableFuture Java 8 not in the PDFs

The other big Java 8 feature, and one interviewers pair with streams: a Future you can chain, combine and complete instead of blocking on. Async code written like a stream pipeline.

Core concept

Future.get() blocks and cannot be chained. CompletableFuture implements CompletionStage: you attach callbacks (thenApply, thenAccept, thenCompose), combine several (thenCombine, allOf, anyOf) and handle errors (exceptionally, handle). Without an executor, tasks run on the common ForkJoinPool; the *Async variants take your own.

CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> fetchUser(id), executor);

cf.thenApply(User::name)                          // map
  .thenCompose(name -> lookupAsync(name))         // flatMap: the function itself returns a CompletableFuture
  .thenAccept(System.out::println)                // consume, returns CF<Void>
  .exceptionally(ex -> { log(ex); return null; })  // recover
  .join();                                        // like get() without checked exceptions

// combine two independent calls
CompletableFuture<Order> order = supplyAsync(() -> orderSvc.get(id));
CompletableFuture<User>  user  = supplyAsync(() -> userSvc.get(uid));
order.thenCombine(user, (o, u) -> new OrderView(o, u));

// fan out, wait for all - the classic "call N services in parallel"
List<CompletableFuture<Price>> futures = shops.stream()
    .map(s -> supplyAsync(() -> s.price(item), executor)).toList();
CompletableFuture.allOf(futures.toArray(CompletableFuture[]::new)).join();
List<Price> prices = futures.stream().map(CompletableFuture::join).toList();

cf.handle((val, ex) -> ex == null ? val : fallback);   // always runs

Records (16)

Definition

A record is an immutable data carrier. From record Point(int x, int y) {} the compiler generates: private final fields, a canonical constructor, accessors named x() / y() (no get prefix), and value-based equals, hashCode, toString (Point[x=1, y=2]). Records are implicitly final, extend java.lang.Record, and cannot declare extra instance fields.

You state exactly which classes may extend you, so the hierarchy is closed and known. Combined with switch pattern matching (Java 21) the compiler verifies every case is handled — algebraic data types in Java: Result = Success | Failure, Shape = Circle | Square.

Virtual threads (21) — the headline

Core concept

A platform thread maps 1:1 to an OS thread (~1 MB stack, expensive to create), so a server could run a few thousand. A virtual thread is a cheap JVM-managed thread: when it blocks on I/O the JVM unmounts it and reuses the carrier OS thread for another. Millions can exist. You write plain blocking code and get async-level scalability — no reactive rewrite.

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 1_000_000; i++) {
        executor.submit(() -> fetchData());          // ordinary blocking call inside
    }
}                                                    // close() waits for all tasks
Thread.startVirtualThread(() -> work());
Thread t = Thread.ofVirtual().name("worker-", 0).unstarted(task);

Trap — when NOT to use virtual threads
  • CPU-bound work gains nothing — you are limited by cores, not thread count.
  • Pinning: a virtual thread blocked inside a synchronized block (or native call) cannot unmount and holds its carrier. Use ReentrantLock around blocking I/O (fixed in Java 24).
  • Do not pool them — create one per task. Do not use ThreadLocal for heavy per-thread caches (millions of copies); use scoped values.
  • Connection pools (HikariCP) are still the bottleneck: a million virtual threads share 10 DB connections.

21Most-asked questions high frequency

The questions that appear in almost every Java 8+ round, with the answer that gets full marks. every round = expect it; common = most rounds; senior = 3+ years.

What are the main features of Java 8? every round

Lambda expressions, functional interfaces (java.util.function), Stream API, default and static methods in interfaces, Optional, the new Date/Time API (java.time), method references, CompletableFuture, Nashorn JS engine, and PermGen replaced by Metaspace. Then name the one you use most and why — that is what they are really asking.

What is a lambda expression and why was it added? every round

An anonymous function — parameters, arrow, body — that implements the single abstract method of a functional interface. Added so behaviour can be passed as data without anonymous-class boilerplate, enabling the Stream API. Its type comes from the target context; it has no type on its own.

What is a functional interface? Can it have default methods? every round

An interface with exactly one abstract method (SAM). It may have any number of default and static methods; Object-method overrides do not count. @FunctionalInterface makes the compiler enforce the rule. Examples: Runnable, Comparator, Callable, Predicate, Function, Consumer, Supplier.

Predicate vs Function vs Consumer vs Supplier? every round

Predicate: T → boolean (test), used in filter. Function: T → R (apply), used in map. Consumer: T → void (accept), used in forEach. Supplier: () → T (get), used for lazy values and orElseGet. Bonus: BiFunction, UnaryOperator, BinaryOperator.

What is the Stream API? Stream vs Collection? every round

A stream is a pipeline for processing a sequence of elements declaratively (filter, map, reduce). A Collection stores data and is traversed as often as you like; a Stream stores nothing, is lazy, is consumed once, can be infinite, and does not modify its source. Collections are about data, streams are about computation.

Intermediate vs terminal operations — and why does laziness matter? every round

Intermediate ops return a stream and are lazy; terminal ops trigger execution and return a result. Nothing runs until the terminal op. Benefits: one fused pass instead of one per stage, and short-circuiting (limit, findFirst, anyMatch stop early). Demo: a map with a print and no terminal op prints nothing.

map vs flatMap? every round

map is one-to-one: each element becomes exactly one. flatMap is one-to-many: the mapper returns a stream (or collection) per element and they are flattened into one stream. Use it for lists of lists, words in lines, Optional::stream. Same distinction in Optional and CompletableFuture (thenCompose).

What is Optional and where should you not use it? every round

A container for a possibly-absent value, making absence explicit in the return type instead of returning null. Prefer map / orElse / orElseGet / orElseThrow / ifPresent over isPresent + get. Do not use it for fields, method parameters, collection elements, or entity properties; it is not Serializable.

Why default methods in interfaces? Diamond problem? every round

To evolve interfaces without breaking implementations — how stream() was added to Collection. If a class inherits the same default from two interfaces it must override and can call A.super.m(). Class methods always beat interface defaults.

Method reference types? common

Static (Integer::parseInt), bound instance (System.out::println), unbound instance (String::toUpperCase — the first argument becomes the receiver), constructor (ArrayList::new).

What is "effectively final"? common

A local variable that is never reassigned after initialisation. Lambdas and anonymous classes may capture only final or effectively final locals, because the value is copied into the lambda and may outlive the method. You can still mutate the captured object's state, which is why AtomicInteger or a collector is the fix for counters.

Lambda vs anonymous inner class? common

this means the enclosing instance in a lambda, the anonymous object in an inner class. Lambdas compile via invokedynamic with no extra class file, create no new scope, and implement exactly one method; anonymous classes can hold state, define several methods and extend classes.

Comparable vs Comparator; how do you sort by multiple fields? every round

Comparable is the class's natural order (compareTo); Comparator is an external order. Multi-field: Comparator.comparing(Emp::dept).thenComparing(Emp::salary, Comparator.reverseOrder()).thenComparing(Emp::name). Use comparingInt to avoid boxing; never a - b.

reduce vs collect? common

reduce folds to one immutable value with an associative operation (sum, max). collect does a mutable reduction into a container (List, Map, StringBuilder) and powers grouping / partitioning / statistics. String concatenation with reduce is O(n²); joining is O(n).

groupingBy vs partitioningBy? common

groupingBy(classifier) makes one key per distinct classifier result. partitioningBy(predicate) always yields exactly two keys, true and false, even if one is empty. Both accept a downstream collector: counting(), mapping(), summingInt(), maxBy().

What happens with duplicate keys in Collectors.toMap? common

IllegalStateException: Duplicate key. Supply the third argument, a merge function: (a, b) -> a keeps the first, Integer::sum combines. A null value throws NPE too. The fourth argument chooses the map type (LinkedHashMap::new).

findFirst vs findAny; anyMatch / allMatch on an empty stream? common

findFirst honours encounter order; findAny may return any element and is cheaper in parallel. On an empty stream allMatch and noneMatch return true, anyMatch false.

When would you use a parallel stream, and when not? every round

Only for large (10k+), CPU-bound, stateless work over a cheaply-splittable source (array, ArrayList, range) — and after measuring. Not for I/O (blocks the shared common ForkJoinPool), small data, order-dependent logic, or lambdas touching shared state. In a web app, prefer an executor or virtual threads.

Why can't you reuse a stream? common

A stream is bound to one traversal; after a terminal operation it is closed and any further use throws IllegalStateException: stream has already been operated upon or closed. Get a new one from the source, or keep a Supplier<Stream<T>>.

Why the new Date/Time API? common

Date/Calendar were mutable, not thread-safe, zero-indexed months, and SimpleDateFormat was not thread-safe. java.time is immutable, thread-safe, and has distinct types: LocalDate, LocalDateTime, ZonedDateTime, Instant, Duration, Period, DateTimeFormatter.

Future vs CompletableFuture? common

Future only blocks on get(). CompletableFuture chains (thenApply, thenCompose), combines (thenCombine, allOf), handles errors (exceptionally, handle), can be completed manually, supports timeouts, and takes a custom executor. Without an executor it uses the common ForkJoinPool.

What changed in HashMap in Java 8? common

Buckets that grow beyond 8 entries (with table size ≥ 64) turn from a linked list into a red-black tree, so worst-case lookup dropped from O(n) to O(log n) — a defence against hash-collision attacks. Also new methods: getOrDefault, putIfAbsent, computeIfAbsent, merge, forEach.

Metaspace vs PermGen? common

Java 8 removed PermGen (fixed-size, in the heap, frequent OutOfMemoryError: PermGen space). Class metadata now lives in Metaspace, in native memory, growing automatically (capped by -XX:MaxMetaspaceSize); interned strings and static variables moved to the heap in Java 7/8.

What is a record and what does the compiler generate? every round

Java 16 immutable data carrier. Generates private final fields, canonical constructor, accessors x(), and value-based equals/hashCode/toString. Compact constructor for validation. Cannot extend a class or add mutable instance fields. Ideal DTOs and map keys.

What are sealed classes for? common

Java 17: restrict which classes may extend or implement a type via permits. Gives a closed hierarchy the compiler knows, enabling exhaustive switch pattern matching without default. Subtypes must be final, sealed or non-sealed.

What are virtual threads and when should you not use them? every round (Java 21+)

Lightweight JVM-managed threads (Java 21); millions can exist; when one blocks on I/O the JVM unmounts it from its carrier OS thread. Write blocking code, scale like async. Not for CPU-bound work; avoid pinning with synchronized around blocking calls; do not pool them; the DB connection pool is still the limit.

Switch expression vs switch statement? common

Java 14: arrow labels, no fall-through, returns a value (yield in blocks), multiple labels per case, exhaustiveness checked. Java 21 adds type patterns, guards (when) and case null.

What does var do — is Java dynamically typed now? common

No. var (Java 10) is local-variable type inference: the compiler fixes the static type from the initialiser. Locals with initialisers only; not fields, parameters or null. var list = new ArrayList<>() infers ArrayList<Object>.

Text blocks — how is indentation handled? senior

Java 15 """ literals. Incidental leading whitespace is stripped based on the least-indented line and the position of the closing delimiter; \ at line end joins lines, \s keeps a trailing space, formatted() substitutes values.

Difference between LTS and non-LTS; what do you target today? common

LTS (8, 11, 17, 21, 25) get years of updates and are what production runs; non-LTS ship every six months as proving grounds. New projects: 21 or 25. Spring Boot 3 needs 17+.

Explain Collectors.groupingBy with a downstream collector using an employee example. every round

"Count per department": groupingBy(Emp::dept, counting()). "Average salary per department": groupingBy(Emp::dept, averagingDouble(Emp::salary)). "Names per department": groupingBy(Emp::dept, mapping(Emp::name, toList())). "Top earner per department": groupingBy(Emp::dept, collectingAndThen(maxBy(comparingDouble(Emp::salary)), Optional::get)). The classifier picks the key; the downstream reduces each group.

Are streams faster than loops? senior

Not inherently; a plain loop is usually equal or slightly faster for simple iteration. Streams win on readability, composability and easy parallelism for CPU-bound bulk work. Boxing (Stream<Integer>) is the usual performance mistake — use IntStream.

What is a Spliterator? senior

The "splittable iterator" under every stream: tryAdvance traverses, trySplit hands half the data to another thread. Its characteristics (SIZED, ORDERED, DISTINCT) let the engine optimise. Custom spliterators turn any source into a parallel-capable stream.

Scoped values vs ThreadLocal? senior

Scoped values (Java 25) are immutable, bound to a where(...).run(...) scope, auto-cleaned, and cheap to inherit by child threads — built for virtual threads. ThreadLocal is mutable, per-thread for the thread's life, leaks in pools, and is copied per inheriting thread.

Why were string templates withdrawn? senior

Previewed in 21–22 (STR."Hello \{name}"), then pulled for redesign; no finalised interpolation exists. Use concatenation, String.format, formatted(), or text blocks. Saying this shows you track the language rather than memorise old blog posts.

22Question bank

Everything else from both guides that section 21 did not already cover. Cover, answer aloud, open.

Can a lambda throw a checked exception?

Only if the functional interface's method declares it (Callable does; Function does not). Otherwise catch and wrap in an unchecked exception, or define a throwing functional interface with an unwrapping helper.

Name three limitations of records.

Implicitly final, cannot extend a class (they extend java.lang.Record); no extra mutable instance fields; accessors are x() not getX(), which JavaBean-based tools may not recognise.

What is a compact constructor?

A canonical constructor without the parameter list: Range { if (low > high) throw ...; }. Runs validation/normalisation; the field assignments happen automatically afterwards. You may reassign the parameters (e.g. tags = List.copyOf(tags)).

Why are records good Map keys?

Value-based equals/hashCode over all components come for free, so equal data hashes and compares equal — exactly HashMap's contract — and immutability means the hash never changes after insertion.

Record patterns vs instanceof patterns?

An instanceof pattern binds the whole object to one variable; a record pattern deconstructs it into components (o instanceof Point(int x, int y)) and nests for nested records.

What are sequenced collections?

Java 21 interfaces SequencedCollection/Set/Map giving every ordered collection getFirst, getLast, addFirst, addLast, removeFirst/Last, reversed().

stream() vs parallelStream() — what changes internally?

The source's spliterator is split recursively; chunks run as ForkJoin tasks on the common pool; results merge via the collector's combiner. Encounter order on forEach is lost; use forEachOrdered.

Which thread pool do parallel streams use and why is that risky?

The common ForkJoinPool (parallelism = cores − 1), shared by the whole JVM. A slow or blocking parallel stream starves every other parallel stream and CompletableFuture default task. Use a dedicated pool for blocking work.

Explain the three forms of reduce.

reduce(identity, acc) → T, never empty. reduce(acc) → Optional<T>. reduce(identity, acc, combiner) → different result type / parallel; the combiner merges partial results.

What must the identity value satisfy?

acc(identity, x) == x for all x. 0 for sum, 1 for product, "" for concat, Integer.MIN_VALUE for max. A wrong identity is applied once per chunk in parallel and corrupts results.

Collectors.toList() vs Stream.toList()?

Stream.toList() (16) is unmodifiable and shorter. Collectors.toList() makes no mutability guarantee (ArrayList in practice). For a specific mutable type: toCollection(ArrayList::new).

orElse vs orElseGet?

orElse(x) evaluates x eagerly, even when a value is present; orElseGet(supplier) only when empty. Use orElseGet for anything expensive.

How do you drop empty Optionals while flat-mapping?

stream.flatMap(Optional::stream) (Java 9): empties become empty streams and vanish.

Why prefer IntStream over Stream<Integer>?

No boxing — raw ints, less memory and GC — plus sum(), average(), summaryStatistics(). Convert with mapToInt / boxed.

What is operation fusion?

Because the pipeline is lazy and processes each element vertically through all stateless stages, filter+map+… are applied in one pass with no intermediate collections.

Does sorted() short-circuit with a later limit()?

No. sorted is a full-buffer stateful op; it must see every element before emitting any, so limit after it only saves the emission, not the sort. On an infinite stream it never terminates.

How do you collect into an unmodifiable Map?

Collectors.toUnmodifiableMap(k, v) (Java 10) or collectingAndThen(toMap(...), Collections::unmodifiableMap).

What does Collectors.teeing do?

Java 12: runs two collectors over the same elements and merges their results with a BiFunction — e.g. min and max, or sum and count for an average, in one pass.

How is a Collector structured?

Supplier (new container), accumulator (add one element), combiner (merge containers in parallel), optional finisher (container → result), plus characteristics UNORDERED / CONCURRENT / IDENTITY_FINISH.

What does peek do and what is the risk?

Runs a Consumer on each element as it flows by, for debugging. The JVM may elide it when the terminal op does not need elements (e.g. count() on a sized stream), so never put logic in it.

Can you make a stream pipeline reusable?

Not the stream object. Keep a Supplier<Stream<T>> and call get() for a fresh pipeline each time.

What is the Java Module System used for?

Java 9: packages grouped into modules declared in module-info.java with requires/exports/opens. Strong encapsulation, reliable configuration, and jlink custom runtimes. Most Boot apps stay on the classpath.

HttpClient vs HttpURLConnection?

Java 11 HttpClient: HTTP/2, sync and async (sendAsync returning CompletableFuture), fluent builder, WebSockets. HttpURLConnection: old, verbose, blocking-only, HTTP/1.1.

What is the Foreign Function & Memory API?

Java 22: call native C functions and manage off-heap memory through a safe typed API; the replacement for JNI with less boilerplate and fewer crashes.

Does Java pass by value or by reference?

Always by value. For objects the value is a copy of the reference: the method can mutate the object but cannot repoint the caller's variable.

Pattern matching for instanceof — what is flow scoping?

if (o instanceof String s) tests, casts and binds. The binding is in scope wherever the compiler can prove the test was true — including after if (!(o instanceof String s)) return;.

What does Stream.iterate with three arguments do?

Java 9: iterate(seed, hasNext, next) — a for-loop as a stream, self-terminating, no limit needed.

takeWhile vs filter?

filter tests every element. takeWhile stops at the first element failing the predicate (and dropWhile starts there) — only meaningful on ordered data, and it short-circuits.

mapMulti vs flatMap?

Java 16 mapMulti pushes 0..n results per element into a consumer without creating a stream per element — faster on hot paths with small expansions. flatMap is clearer when you already have a collection to flatten.

What are gatherers?

Java 24: user-defined lazy intermediate operations via stream.gather(...); built-ins windowFixed, windowSliding, fold, scan, mapConcurrent. The intermediate counterpart of Collector.

List.of vs Arrays.asList?

List.of: immutable, rejects null. Arrays.asList: fixed-size view over the array — set works, add/remove throw, changes write through to the array.

What are helpful NullPointerExceptions?

Java 14: the message names the exact null expression — Cannot invoke "String.length()" because "user.name" is null.

Why does Java not have string interpolation?

The string-template preview was withdrawn for redesign. Use formatted(), String.format, concatenation or text blocks until a redesigned feature lands.

How do you handle a checked exception inside a stream map?

Wrap: map(p -> { try { return Files.readString(p); } catch (IOException e) { throw new UncheckedIOException(e); } }), or a helper unchecked(ThrowingFunction) that does the wrapping once.

What is the difference between Collection.removeIf and a stream filter?

removeIf (Java 8, default method) mutates the collection in place using a Predicate — the right tool when you want to modify the original. A stream filter produces a new result and leaves the source untouched.

Map.computeIfAbsent / merge / getOrDefault — when?

getOrDefault: read with fallback. computeIfAbsent(k, k -> new ArrayList<>()): build-or-get for multimaps. merge(k, 1, Integer::sum): counting. compute: update based on the old value. All Java 8 defaults on Map.

23What's the output?

Predict before you open. These test laziness, short-circuiting and stream reuse — the three things interviewers trap you with.

No terminal operation 
Stream.of("a","b","c").map(s -> { System.out.println("mapping " + s); return s.toUpperCase(); });

Nothing is printed. map is lazy; without a terminal operation the pipeline never runs.

peek + limit 
Stream.of(1,2,3,4,5).peek(n -> System.out.print("p" + n + " ")).limit(2).forEach(n -> System.out.print("f" + n + " "));

p1 f1 p2 f2 — vertical processing, one element at a time; limit(2) short-circuits so 3, 4, 5 are never peeked.

allMatch on empty 
System.out.println(Stream.<Integer>empty().allMatch(n -> n > 5));

true — vacuous truth. noneMatch is also true; anyMatch is false.

Reused stream 
Stream<Integer> s = Stream.of(1,2,3);
s.count();
s.forEach(System.out::println);

IllegalStateException: stream has already been operated upon or closed.

flatMap on split 
Stream.of("a b","c d").flatMap(l -> Arrays.stream(l.split(" "))).forEach(System.out::print);

abcd — the two per-line streams are flattened into one stream of four words.

sorted then filter with prints 
Stream.of(3,1,2).sorted().peek(n -> System.out.print("s" + n)).filter(n -> n > 1).forEach(n -> System.out.print("f" + n));

s1s2f2s3f3 — sorted buffers all three, then emits them one at a time through the rest of the pipeline.

Optional.orElse side effect 
String v = Optional.of("x").orElse(build());   // build() prints "building"

building is printed even though the value is present — orElse is eager. orElseGet(() -> build()) would print nothing.

Integer cache in a stream 
List<Integer> a = List.of(127, 128);
System.out.println(a.stream().map(i -> i == Integer.valueOf(127) || i == Integer.valueOf(128)).toList());

[true, false] — 127 hits the Integer cache (−128..127), 128 does not, and == compares references. Use equals.

Effectively final 
int sum = 0;
List.of(1,2).forEach(x -> sum += x);

Compile error: "local variables referenced from a lambda expression must be final or effectively final".

Stream.of on an int[] 
System.out.println(Stream.of(new int[]{1,2,3}).count());

1 — one element, the array itself. Arrays.stream(arr).count() gives 3.

Parallel forEach order 
List.of(1,2,3,4,5).parallelStream().forEach(System.out::print);

Non-deterministic, e.g. 34512. forEachOrdered prints 12345. toList() still preserves order — collectors do.

toMap duplicate 
Stream.of("aa","bb").collect(Collectors.toMap(String::length, s -> s));

IllegalStateException: Duplicate key 2. Add (a, b) -> a.

The eight traps to recite before the interview
  1. Streams are lazy; no terminal op = nothing runs. Consumed once.
  2. allMatch/noneMatch on empty = true. max/findFirst = Optional.
  3. toMap: duplicate key throws; null value throws; add the merge function.
  4. orElse is eager; orElseGet is lazy.
  5. sorted buffers everything; never on an infinite stream before limit.
  6. Parallel: common pool, no order, no shared state, no I/O; measure first.
  7. Captured locals must be effectively final; this in a lambda is the enclosing object.
  8. Stream.of(int[]) is one element; var list = new ArrayList<>() is ArrayList<Object>; a - b overflows.

Final word

Every question in this page reduces to five ideas: behaviour as data (lambdas), pipelines that are lazy and consumed once (streams), absence in the type (Optional), data as immutable values (records, sealed types), and cheap blocking (virtual threads). Explain those five with one example each and you can derive the rest at the whiteboard.
