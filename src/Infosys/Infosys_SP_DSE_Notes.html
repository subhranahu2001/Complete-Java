02Fast I/O & Java cheat sheet

Infosys often uses full-program stdin/stdout. Scanner on 105 lines is a TLE; this template is not. Memorise it — you type it in the first two minutes of every problem.

import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int n = Integer.parseInt(st.nextToken());

        int[] a = new int[n];
        st = new StringTokenizer(br.readLine());          // all n numbers on one line
        for (int i = 0; i < n; i++) a[i] = Integer.parseInt(st.nextToken());
        // numbers on separate lines: a[i] = Integer.parseInt(br.readLine().trim());

        StringBuilder out = new StringBuilder();
        // ... solve ...
        out.append(answer).append('\n');
        System.out.print(out);
    }
}

// robust token reader when the layout is unknown (tokens may span lines)
static StringTokenizer tk;
static String next(BufferedReader br) throws IOException {
    while (tk == null || !tk.hasMoreTokens()) tk = new StringTokenizer(br.readLine());
    return tk.nextToken();
}
Scanner traps
  • After nextInt(), a following nextLine() returns the rest of the current line (usually empty) — call nextLine() once to consume it.
  • Scanner is fine for n ≤ 104. Above that, BufferedReader.
  • Print with one StringBuilder and a single System.out.print. 105 println calls can TLE on their own.

Small things that save minutes
  • Sorting: Arrays.sort(int[]) takes no comparator — box to Integer[] or sort indices. Collections.reverseOrder() for descending.
  • Char math: ch - 'a' → 0..25; (char)('a' + i) back; Character.isDigit / isLetter / toLowerCase.
  • Strings: s.substring(i, j) (j exclusive), s.split(" +"), s.trim(), String.join(" ", list).
  • Numbers: Long.parseLong, Integer.toBinaryString(n), Integer.parseInt(s, 2), Integer.bitCount.
  • Overflow: long for sums, products, factorials, prefix sums. Cast before multiplying: (long) a * b.
  • Modulo: final int MOD = 1_000_000_007; apply after every multiplication and addition. Negative: ((x % m) + m) % m.
  • Compare Integers with .equals(), not == (breaks above 127).
  • Debug: System.err.println is ignored by judges.

03P1 — Basic string & number manipulation Easy

Recognise it

Statement talks about digits, characters, reversing, checking a property (palindrome, Armstrong, prime), or printing a shape. No constraints on n beyond small values.

Core idea: loop over characters or digits. Digits: n % 10 and n / 10. Characters: toCharArray() + StringBuilder. Know the classic definitions exactly. O(n) or O(digits); prime check O(√n).

// reverse a number
long rev = 0; long x = n;
while (x > 0) { rev = rev * 10 + x % 10; x /= 10; }

// palindrome string (two pointers)
boolean isPal(String s) {
    int i = 0, j = s.length() - 1;
    while (i < j) if (s.charAt(i++) != s.charAt(j--)) return false;
    return true;
}

// prime check
boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; (long) i * i <= n; i++) if (n % i == 0) return false;
    return true;
}

// Armstrong: 153 -> 1^3 + 5^3 + 3^3
boolean armstrong(int n) {
    int d = String.valueOf(n).length(); long sum = 0;
    for (int x = n; x > 0; x /= 10) sum += (long) Math.pow(x % 10, d);
    return sum == n;
}

// pyramid, rows = r
for (int i = 1; i <= r; i++) {
    StringBuilder sb = new StringBuilder();
    for (int s = 0; s < r - i; s++) sb.append(' ');
    for (int k = 0; k < 2 * i - 1; k++) sb.append('*');
    System.out.println(sb);
}
Pitfalls
  • Reversing a number that overflows int — use long.
  • 0 and 1 are not prime.
  • String concatenation in a loop instead of StringBuilder.

04P2 — Array fundamentals Easy

Recognise it

Largest / second largest, remove duplicates, rotate, missing or duplicate number, count occurrences, leaders. n up to 105 means no nested loops.

Core idea: single pass with tracking variables, one sort, or a frequency array. Missing number in 1..N: sum formula or XOR. Rotation: reversal trick.

// second largest without sorting
int first = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
for (int v : a) {
    if (v > first) { second = first; first = v; }
    else if (v > second && v != first) second = v;
}

// rotate right by k using reversal
void rotate(int[] a, int k) {
    int n = a.length; k %= n;
    rev(a, 0, n - 1); rev(a, 0, k - 1); rev(a, k, n - 1);
}
void rev(int[] a, int i, int j) { while (i < j) { int t = a[i]; a[i++] = a[j]; a[j--] = t; } }

// missing number 1..N (XOR, no overflow)
int x = 0;
for (int i = 1; i <= n; i++) x ^= i;
for (int v : a) x ^= v;              // x is the missing number

// remove duplicates preserving order
LinkedHashSet<Integer> set = new LinkedHashSet<>();
for (int v : a) set.add(v);

// leaders: scan from the right keeping the running max
int mx = Integer.MIN_VALUE;
for (int i = n - 1; i >= 0; i--) if (a[i] >= mx) { mx = a[i]; /* a[i] is a leader */ }
Pitfalls
  • Second largest when all elements are equal — decide what to print (often -1).
  • k larger than n in rotation — always k %= n.
  • n*(n+1)/2 overflowing int — use long or XOR.

05P18 — Math & bit tricks Easy Medium

Recognise it

GCD/LCM, primes up to N, factorial with modulo, power in log time, "count set bits", "single number where others appear twice", "power of two", "swap without temp".

Core idea: Euclid for GCD; sieve for many prime checks; fast exponentiation for ab mod m; XOR cancels pairs; n & (n-1) drops the lowest set bit. GCD O(log n); sieve O(n log log n); fast power O(log b).

long gcd(long a, long b) { return b == 0 ? a : gcd(b, a % b); }
long lcm(long a, long b) { return a / gcd(a, b) * b; }

// sieve of Eratosthenes
boolean[] isP = new boolean[N + 1]; Arrays.fill(isP, true); isP[0] = isP[1] = false;
for (int i = 2; (long) i * i <= N; i++)
    if (isP[i]) for (int j = i * i; j <= N; j += i) isP[j] = false;

// fast power mod
long power(long a, long b, long m) {
    long res = 1; a %= m;
    while (b > 0) { if ((b & 1) == 1) res = res * a % m; a = a * a % m; b >>= 1; }
    return res;
}

// bits
int setBits = Integer.bitCount(n);
boolean powerOfTwo = n > 0 && (n & (n - 1)) == 0;
int single = 0; for (int v : a) single ^= v;         // others appear twice
// ith bit: (n >> i & 1) == 1 ; set: n | (1 << i) ; clear: n & ~(1 << i)

// factorial mod, nCr via Pascal or modular inverse (power(x, MOD-2, MOD))
long f = 1; for (int i = 2; i <= n; i++) f = f * i % MOD;

// trailing zeroes in n!: count factors of 5
int z = 0; for (long p = 5; p <= n; p *= 5) z += n / p;
Pitfalls
  • Math.pow returns double and loses precision above 253 — use long loops or fast power.
  • Sieve inner loop must start at i*i (or 2i); starting at i marks the prime itself.
  • Negative modulo in Java: (x % m + m) % m.

06P3 — Two pointers Medium

Recognise it

Sorted array (or you can sort it) and you need a pair / triplet with a property; an in-place rearrangement; or comparing a string from both ends.

Core idea: one pointer at each end (or slow/fast from the start), move based on a comparison. Each pointer moves at most n times → O(n) after sorting.

// pair with sum target in sorted array
int i = 0, j = a.length - 1;
while (i < j) {
    int s = a[i] + a[j];
    if (s == target) { /* found */ break; }
    else if (s < target) i++; else j--;
}

// remove duplicates in place from sorted array, return new length
int w = 0;
for (int r = 0; r < a.length; r++)
    if (r == 0 || a[r] != a[r - 1]) a[w++] = a[r];

// Dutch national flag: sort 0s, 1s, 2s
int lo = 0, mid = 0, hi = n - 1;
while (mid <= hi) {
    if (a[mid] == 0) swap(a, lo++, mid++);
    else if (a[mid] == 1) mid++;
    else swap(a, mid, hi--);
}

// 3-sum: sort, fix i, two-pointer on the rest; skip duplicates of i, l, r
// container with most water: move the shorter side inward
Pitfalls
  • Forgetting to sort first when the array is not sorted.
  • Off-by-one when pointers cross — while (i < j).
  • Two pointers only works when moving a pointer is guaranteed to move toward the answer; otherwise it is hashing (07).

07P4 — Hashing & frequency counting Medium

Recognise it

"Frequency", "count occurrences", "first non-repeating", "anagram", "pair with sum" on an unsorted array, "distinct", "duplicate". You need O(1) lookups.

Core idea: HashMap (value → count or value → index) or int[26] / int[256] for characters. One pass to build, one to answer. Anagram key = sorted string or 26-count. O(n) time.

// character frequency (lowercase)
int[] f = new int[26];
for (char ch : s.toCharArray()) f[ch - 'a']++;

// frequency of anything
Map<Integer, Integer> cnt = new HashMap<>();
for (int v : a) cnt.merge(v, 1, Integer::sum);

// two sum on unsorted array
Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < a.length; i++) {
    if (seen.containsKey(target - a[i])) { /* pair seen.get(target - a[i]), i */ }
    seen.put(a[i], i);
}

// group anagrams: key = sorted string
Map<String, List<String>> g = new HashMap<>();
for (String w : words) {
    char[] c = w.toCharArray(); Arrays.sort(c);
    g.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);
}

// most frequent, tie -> smallest value
int best = -1, bestC = 0;
for (var e : cnt.entrySet())
    if (e.getValue() > bestC || (e.getValue() == bestC && e.getKey() < best)) { best = e.getKey(); bestC = e.getValue(); }

// longest consecutive sequence: HashSet, start only from v where v-1 is absent
Pitfalls
  • int[26] when input has uppercase, digits or spaces — use int[256] or a map.
  • HashMap iteration order is not insertion order — LinkedHashMap when order matters.
  • Tie-break rules (smallest value, first occurrence) are usually stated — read them.

08P5 — Sliding window Medium

Recognise it

Contiguous "subarray" or "substring" with "longest", "shortest", "maximum sum", "at most K distinct", "window of size K", "without repeating".

Core idea: window [l, r]. Expand r, update running state (sum, counts). When invalid, shrink l until valid. Every index enters and leaves once → O(n). Fixed size: just slide.

// fixed window: max sum of size k
long sum = 0, best = Long.MIN_VALUE;
for (int r = 0; r < a.length; r++) {
    sum += a[r];
    if (r >= k) sum -= a[r - k];
    if (r >= k - 1) best = Math.max(best, sum);
}

// variable window: longest substring without repeating chars
int[] last = new int[256]; Arrays.fill(last, -1);
int l = 0, ans = 0;
for (int r = 0; r < s.length(); r++) {
    char ch = s.charAt(r);
    if (last[ch] >= l) l = last[ch] + 1;      // jump past previous occurrence
    last[ch] = r;
    ans = Math.max(ans, r - l + 1);
}

// count distinct in every window of size k
Map<Integer,Integer> cnt = new HashMap<>();
for (int r = 0; r < a.length; r++) {
    cnt.merge(a[r], 1, Integer::sum);
    if (r >= k) { int out = a[r - k]; if (cnt.merge(out, -1, Integer::sum) == 0) cnt.remove(out); }
    if (r >= k - 1) System.out.print(cnt.size() + " ");
}

// at most K distinct: expand r, while (cnt.size() > K) shrink l
// min window substring: need[] counts of T, "missing" counter; shrink while missing == 0
Pitfalls
  • Sliding window for "sum = K" only works with non-negative numbers; with negatives use prefix sums + HashMap (11).
  • Forgetting to remove the outgoing element's count when it hits zero.
  • Recording answers before the first full window (r >= k - 1).

09P6 — Sorting & custom comparators Medium

Recognise it

"Sort by frequency", "by length then alphabetically", "arrange to form the largest number", "merge intervals", "rank the students" — or any problem that becomes a single scan once sorted.

Core idea: a Comparator that encodes the ordering rule, then one linear pass. O(n log n).

// strings by length, then alphabetically
Arrays.sort(words, (x, y) -> x.length() != y.length() ? x.length() - y.length() : x.compareTo(y));

// by frequency desc, tie by value asc
Integer[] b = ...; Map<Integer,Integer> cnt = ...;
Arrays.sort(b, (x, y) -> cnt.get(x).equals(cnt.get(y)) ? x - y : cnt.get(y) - cnt.get(x));

// students: marks desc, name asc  (rows = String[]{name, mark})
Arrays.sort(rows, (x, y) -> {

Recognise it

// spiral

Core Java — expect 5 to 8

Why is String immutable? String vs StringBuilder vs StringBuffer.

Security (class names, file paths), safe sharing across threads, and the string pool needs it (two variables can share one literal). Hash code can be cached. StringBuilder is mutable and unsynchronised (use it); StringBuffer is synchronised and slower.

== vs .equals(); the equals / hashCode contract.

== compares references; equals compares content. If two objects are equal they must have the same hashCode, otherwise HashMap puts them in different buckets and get fails. Override both together.

How does HashMap work internally?

Array of buckets; index = (h ^ (h >>> 16)) & (n - 1). Collisions chain in a linked list; a bucket with ≥ 8 entries becomes a red-black tree (Java 8). Load factor 0.75 triggers resize to double, rehashing every entry. Null key allowed once. Not thread-safe — ConcurrentHashMap.

ArrayList vs LinkedList; HashMap vs TreeMap vs LinkedHashMap; HashSet vs TreeSet.

ArrayList: O(1) index, O(n) middle insert, cache-friendly — almost always the right choice. LinkedList: O(1) at ends via iterator. HashMap O(1) unordered; LinkedHashMap keeps insertion (or access) order; TreeMap O(log n) sorted with floor / ceiling. Same for the sets.

Abstract class vs interface.

Abstract class: state, constructors, any access modifier, single inheritance — "is-a" with shared code. Interface: contract, multiple inheritance, default and static methods since Java 8, private methods since 9 — "can-do". Functional interface = exactly one abstract method, target of a lambda.

Overloading vs overriding; can you override static or private methods?

Overloading: same name, different parameters, resolved at compile time. Overriding: subclass replaces an inherited method, resolved at runtime (dynamic dispatch). Static methods are hidden, not overridden; private methods are not inherited, so neither is overridable.

Exception hierarchy; checked vs unchecked; finally vs return.

Throwable → Error (JVM, do not catch) and Exception; RuntimeException and its subclasses are unchecked. Checked must be declared or caught. finally always runs; a return inside finally overrides the try's return (never do it). try-with-resources closes AutoCloseable in reverse order.

Java 8: lambdas, streams, Optional, method references.

Lambda implements a functional interface. Streams: filter / map / sorted / collect; Collectors.groupingBy, counting, joining; lazy until a terminal op. Optional avoids null returns: orElse, map, ifPresent. Method reference Integer::sum, String::length.

final, finally, finalize; static blocks; access modifiers.

final: constant / no override / no subclass. finally: cleanup block. finalize: deprecated GC hook. Static block runs once at class load, before main. private < default (package) < protected (package + subclasses) < public.

JDK vs JRE vs JVM; heap vs stack; garbage collection.

JDK = compiler + tools + JRE; JRE = libraries + JVM; JVM runs bytecode. Stack: per-thread frames, primitives and references. Heap: objects, shared. GC frees unreachable objects; generational (young / old); System.gc() is a hint only.

Thread vs Runnable; synchronized; volatile; ExecutorService; deadlock.

Implement Runnable (or Callable for a result) and hand it to an ExecutorService; extending Thread wastes the single inheritance. synchronized: mutual exclusion + visibility on a monitor. volatile: visibility only, no atomicity. Deadlock: two threads holding locks the other needs — prevent with a fixed lock order or tryLock.

SOLID in one line each.

Single responsibility; Open for extension, closed for modification; Liskov substitutable subtypes; Interface segregation (small interfaces); Dependency inversion (depend on abstractions, inject them).

DBMS — expect 2 to 4

ACID properties.

Atomicity (all or nothing), Consistency (constraints hold), Isolation (concurrent transactions do not see each other's partial work — levels: read uncommitted, read committed, repeatable read, serializable), Durability (committed survives crashes).

Inner vs left vs right vs full join; WHERE vs HAVING.

Inner: matching rows only. Left: all left rows, nulls for missing right. Right: mirror. Full: both. WHERE filters rows before grouping; HAVING filters groups after aggregation.

Primary vs foreign vs unique key; index.

Primary: unique + not null, one per table. Unique: no duplicates, nulls allowed. Foreign: references another table's primary key, enforces referential integrity. Index: B-tree on columns to speed lookups at the cost of writes.

Normalisation 1NF, 2NF, 3NF.

1NF: atomic values, no repeating groups. 2NF: 1NF + no partial dependency on part of a composite key. 3NF: 2NF + no transitive dependency (non-key depends only on the key).

Write: second highest salary; employees per department with count > 5.

SELECT MAX(sal) FROM emp WHERE sal < (SELECT MAX(sal) FROM emp);   SELECT dept, COUNT(*) FROM emp GROUP BY dept HAVING COUNT(*) > 5;

OS & networks — expect 1 to 2

Process vs thread.

Process: own address space, heavier, isolated. Thread: shares the process memory, cheaper to create and switch, needs synchronisation.

Four conditions for deadlock.

Mutual exclusion, hold and wait, no preemption, circular wait. Break any one to prevent it.

Paging; TCP vs UDP; common HTTP methods and codes.

Paging: fixed-size pages mapped to frames, page table, page fault loads from disk. TCP: connection, ordered, reliable. UDP: connectionless, fast, lossy. GET / POST / PUT / DELETE; 200, 201, 400, 401, 403, 404, 500.
